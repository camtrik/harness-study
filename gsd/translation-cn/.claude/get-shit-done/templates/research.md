# 研究模板

`.planning/phases/XX-name/{phase_num}-RESEARCH.md` 的模板——规划前的全面生态系统研究。

**目的：** 记录 Claude 为了很好地实现一个阶段需要知道什么——不仅仅是"用哪个库"而是"专家是怎么构建这个的"。

## 架构模式

### 系统架构图

架构图必须展示数据流经概念组件的过程，而非文件列表。

要求：
- 展示入口点（数据/请求如何进入系统）
- 展示处理阶段（发生什么转换，以什么顺序）
- 展示决策点和分支路径
- 展示外部依赖和服务边界
- 使用箭头指示数据流方向
- 读者应能通过追溯箭头，从输入到输出追踪主要用例

文件到实现的映射属于组件职责表，而非图表。

## 优秀示例

```markdown
# 阶段 3：3D 城市驾驶 - 研究

**研究日期：** 2025-01-20
**领域：** 带驾驶机制的 Three.js 3D 网页游戏
**置信度：** HIGH

<research_summary>
## 摘要

研究了 Three.js 生态系统中构建 3D 城市驾驶游戏的方法。标准做法使用 Three.js 配合 React Three Fiber 实现组件化架构、Rapier 用于物理引擎、drei 用于通用辅助函数。

关键发现：不要自己实现物理或碰撞检测。Rapier（通过 @react-three/rapier）高效处理车辆物理、地形碰撞和城市物体交互。自定义物理代码会导致 bug 和性能问题。

**主要推荐：** 使用 R3F + Rapier + drei 技术栈。从 drei 的车辆控制器开始，添加 Rapier 车辆物理，使用实例化网格构建城市以优化性能。
</research_summary>

<standard_stack>
## 标准技术栈

### 核心
| 库 | 版本 | 用途 | 为什么是标准 |
|---------|---------|---------|--------------|
| three | 0.160.0 | 3D 渲染 | Web 3D 的标准 |
| @react-three/fiber | 8.15.0 | Three.js 的 React 渲染器 | 声明式 3D，更好的开发体验 |
| @react-three/drei | 9.92.0 | 辅助函数和抽象 | 解决常见问题 |
| @react-three/rapier | 1.2.1 | 物理引擎绑定 | R3F 的最佳物理引擎 |

### 支持
| 库 | 版本 | 用途 | 何时使用 |
|---------|---------|---------|-------------|
| @react-three/postprocessing | 2.16.0 | 视觉效果 | 辉光、景深、运动模糊 |
| leva | 0.9.35 | 调试 UI | 调整参数 |
| zustand | 4.4.7 | 状态管理 | 游戏状态、UI 状态 |
| use-sound | 4.0.1 | 音频 | 引擎声、环境音 |

### 考虑过的替代方案
| 不使用 | 可使用 | 权衡 |
|------------|-----------|----------|
| Rapier | Cannon.js | Cannon 更简单但车辆性能较差 |
| R3F | 原生 Three | 如果不用 React 可用原生，但 R3F 开发体验好得多 |
| drei | 自定义辅助函数 | drei 经过实战检验，不要重复造轮子 |

**安装：**
```bash
npm install three @react-three/fiber @react-three/drei @react-three/rapier zustand
```
</standard_stack>
```
