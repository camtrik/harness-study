`.planning/REQUIREMENTS.md` 的模板——定义"完成"的可检查需求。

<template>

<guidelines>

**需求格式：**
- ID：`[CATEGORY]-[NUMBER]`（AUTH-01、CONTENT-02、SOCIAL-03）
- 描述：以用户为中心、可测试、原子性
- 复选框：仅用于 v1 需求（v2 尚不可执行）

**分类：**
- 从研究 FEATURES.md 的分类中推导
- 与领域约定保持一致
- 典型：认证、内容、社交、通知、审核、支付、管理

**v1 vs v2：**
- v1：已承诺范围，将在路线图阶段中
- v2：已确认但延迟，不在当前路线图中
- 将 v2 → v1 需要路线图更新

**排除范围：**
- 明确排除项，附推理
- 防止后续"为什么没包含 X？"的疑问
- 研究中发现的反功能应在此处附警告

**可追溯性：**
- 初始为空，在路线图创建期间填充
- 每个需求精确映射到一个阶段
- 未映射的需求 = 路线图缺口

**状态值：**
- 待处理：未开始
- 进行中：阶段活跃
- 已完成：需求已验证
- 阻塞：等待外部因素

</guidelines>

<evolution>

**每个阶段完成后：**
1. 将覆盖的需求标记为已完成
2. 更新可追溯性状态
3. 注明任何范围有变化的需求

**路线图更新后：**
1. 验证所有 v1 需求仍然有映射
2. 如果范围扩展则添加新需求
3. 如果范围缩小则将需求移至 v2/排除范围

**需求完成标准：**
- 需求为"已完成"时：
  - 功能已实现
  - 功能已验证（测试通过，手动检查完成）
  - 功能已提交

</evolution>

**定义日期：** 2025-01-14
**核心价值：** 用户可以与有共同兴趣的人分享和讨论内容

## v1 需求

### 认证

- [ ] **AUTH-01**：用户可以使用邮箱和密码注册
- [ ] **AUTH-02**：用户注册后收到邮箱验证
- [ ] **AUTH-03**：用户可以通过邮箱链接重置密码
- [ ] **AUTH-04**：用户会话在浏览器刷新后持久保留

### 个人资料

- [ ] **PROF-01**：用户可以创建带显示名称的个人资料
- [ ] **PROF-02**：用户可以上传头像图片
- [ ] **PROF-03**：用户可以编写个人简介（最多 500 字）
- [ ] **PROF-04**：用户可以查看其他用户的个人资料

### 内容

- [ ] **CONT-01**：用户可以创建文本帖子
- [ ] **CONT-02**：用户可以在帖子中上传图片
- [ ] **CONT-03**：用户可以编辑自己的帖子
- [ ] **CONT-04**：用户可以删除自己的帖子
- [ ] **CONT-05**：用户可以查看帖子信息流

### 社交

- [ ] **SOCL-01**：用户可以关注其他用户
- [ ] **SOCL-02**：用户可以取消关注
- [ ] **SOCL-03**：用户可以点赞帖子
- [ ] **SOCL-04**：用户可以评论帖子
- [ ] **SOCL-05**：用户可以查看活动信息流（已关注用户的帖子）

## v2 需求

### 通知

- **NOTF-01**：用户收到应用内通知
- **NOTF-02**：用户收到新粉丝的邮件通知
- **NOTF-03**：用户收到自己帖子的评论邮件通知
- **NOTF-04**：用户可以配置通知偏好

### 审核

- **MODR-01**：用户可以举报内容
- **MODR-02**：用户可以屏蔽其他用户
- **MODR-03**：管理员可以查看被举报内容
- **MODR-04**：管理员可以移除内容
- **MODR-05**：管理员可以封禁用户

| 移动应用 | 优先 Web，移动端稍后 |
