# 代码库关注点模板

`.planning/codebase/CONCERNS.md` 的模板——记录已知问题和需要谨慎处理的领域。

**目的：** 呈现关于代码库的可执行警告。聚焦于"修改时需要留意什么"。

<good_examples>
```markdown
# 代码库关注点

**分析日期：** 2025-01-20

## 技术债务

**React 组件中的数据库查询：**
- 问题：15+ 个页面组件中直接使用 Supabase 查询，而非使用 server actions
- 文件：`app/dashboard/page.tsx`、`app/profile/page.tsx`、`app/courses/[id]/page.tsx`、`app/settings/page.tsx`（以及 `app/` 中的另外 11 个文件）
- 原因：MVP 阶段的快速原型开发
- 影响：无法正确实现 RLS，将数据库结构暴露给客户端
- 修复方法：将所有查询移至 `app/actions/` 中的 server actions，添加正确的 RLS 策略

**手动 webhook 签名验证：**
- 问题：在 3 个不同的端点中复制粘贴了 Stripe webhook 验证代码
- 文件：`app/api/webhooks/stripe/route.ts`、`app/api/webhooks/checkout/route.ts`、`app/api/webhooks/subscription/route.ts`
- 原因：每个 webhook 都是临时添加的，没有抽象
- 影响：新 webhook 中容易遗漏验证（安全风险）
- 修复方法：创建共享的 `lib/stripe/validate-webhook.ts` 中间件

## 已知 Bug

**订阅更新中的竞态条件：**
- 症状：成功支付后，用户显示为"免费"层级 5-10 秒
- 触发条件：Stripe 结账重定向后的快速导航，在 webhook 处理之前
- 文件：`app/checkout/success/page.tsx`（重定向处理函数）、`app/api/webhooks/stripe/route.ts`（webhook）
- 临时方案：Stripe webhook 最终更新状态（自愈）
- 根因：Webhook 处理比用户导航慢，无乐观 UI 更新
- 修复：在 `app/checkout/success/page.tsx` 中重定向后添加轮询

**登出后不稳定的会话状态：**
- 症状：登出后用户被重定向到 /dashboard 而非 /login
- 触发条件：通过移动端导航中的按钮登出（桌面端正常）
- 文件：`components/MobileNav.tsx`（大约第 45 行，登出处理函数）
- 临时方案：手动 URL 导航到 /login 可行
- 根因：移动导航组件未 await supabase.auth.signOut()
- 修复：在 `components/MobileNav.tsx` 的登出处理函数中添加 await

## 安全注意事项

**仅客户端检查的管理员角色：**
- 风险：管理员仪表盘页面从 Supabase 客户端检查 isAdmin，无服务器端验证
- 文件：`app/admin/page.tsx`、`app/admin/users/page.tsx`、`components/AdminGuard.tsx`
- 当前缓解措施：无（依赖 UI 隐藏）
- 建议：在 `middleware.ts` 中为管理路由添加中间件，在服务器端验证角色

**未验证的文件上传：**
- 风险：用户可以上传任何文件类型到头像桶（无大小/类型验证）
- 文件：`components/AvatarUpload.tsx`（上传处理函数）
- 当前缓解措施：Supabase 桶限制为 2MB（在仪表盘配置）
- 建议：在 `lib/storage/validate.ts` 中添加文件类型验证（仅 image/*）

## 性能瓶颈

**/api/courses 端点：**
- 问题：获取所有课程及嵌套的课程章节和作者
- 文件：`app/api/courses/route.ts`
- 测量值：50+ 课程时 p95 响应时间 1.2s
- 原因：N+1 查询模式（每个课程单独查询其章节）
- 改进路径：使用 Prisma include 在 `lib/db/courses.ts` 中预加载课程章节，添加 Redis 缓存

**仪表盘初始加载：**
- 问题：挂载时 5 个串行 API 调用的瀑布流
- 文件：`app/dashboard/page.tsx`
- 测量值：慢速 3G 下 3.5s 才可交互
- 原因：每个组件独立获取自己的数据
- 改进路径：转换为 Server Component 并使用单个并行 fetch

## 脆弱领域

**认证中间件链：**
- 文件：`middleware.ts`
- 为什么脆弱：4 个不同的中间件函数按特定顺序运行（auth → role → subscription → logging）
- 常见故障：中间件顺序变更导致一切出错，调试困难
- 安全修改：在更改顺序前添加测试，在注释中记录依赖关系
- 测试覆盖：中间件链没有集成测试（仅有单元测试）

**Stripe webhook 事件处理：**
- 文件：`app/api/webhooks/stripe/route.ts`
- 为什么脆弱：巨大的 switch 语句含 12 种事件类型，共享事务逻辑
- 常见故障：添加新事件类型但未处理，错误时部分数据库更新
- 安全修改：将每个事件处理函数提取到 `lib/stripe/handlers/*.ts`
- 测试覆盖：12 种事件类型中仅有 3 种有测试

## 伸缩限制

**Supabase 免费层：**
- 当前容量：500MB 数据库，1GB 文件存储，2GB 带宽/月
- 限制：估计在达到限制前约 5000 用户
- 达到限制时的症状：429 速率限制错误，数据库写入失败
- 伸缩路径：升级到 Pro（$25/月）扩展到 8GB 数据库，100GB 存储

**服务器端渲染阻塞：**
- 当前容量：约 50 并发用户之前性能下降
- 限制：Vercel Hobby 计划（10s 函数超时，100GB-hrs/月）
- 达到限制时的症状：课程页面 504 网关超时
- 伸缩路径：升级到 Vercel Pro（$20/月），添加边缘缓存

## 有风险的依赖

**react-hot-toast：**
- 风险：无维护（上次更新 18 个月前），React 19 兼容性未知
- 影响：Toast 通知失效，无优雅降级
- 迁移计划：切换到 sonner（活跃维护，API 类似）

## 缺失的关键功能

**支付失败处理：**
- 问题：订阅支付失败时无重试机制或用户通知
- 当前临时方案：用户手动重新输入支付信息（如果他们注意到了的话）
- 阻塞：无法留住卡过期的用户，无催款流程
- 实现复杂度：中（Stripe webhooks + 邮件流程 + UI）

**课程进度跟踪：**
- 问题：没有哪些课时已完成的持久状态
- 当前临时方案：用户手动跟踪进度
- 阻塞：无法显示完成百分比，无法推荐下一课
- 实现复杂度：低（添加 completed_lessons 关联表）

## 测试覆盖缺口

**支付流程端到端：**
- 未测试的内容：完整的 Stripe 结账 → webhook → 订阅激活流程
- 风险：支付处理可能无声失败（已发生两次）
- 优先级：高
- 测试难度：需要 Stripe 测试夹具和 webhook 模拟设置

**错误边界行为：**
- 未测试的内容：当组件抛出错误时应用的行为
- 风险：用户看到白屏死机，无错误报告
- 优先级：中
- 测试难度：需要在测试环境中故意触发错误

---

*关注点审计：2025-01-20*
*当问题被修复或新问题被发现时更新*
```

<guidelines>
**CONCERNS.md 应包含的内容：**
- 有明确影响和修复方法的 技术债务
- 有复现步骤的已知 Bug
- 安全缺口及缓解建议
- 有测量值的性能瓶颈
- 容易出问题的脆弱代码
- 有数字的伸缩限制
- 需要关注的依赖
- 阻塞工作流的缺失功能
- 测试覆盖缺口

**不应包含的内容：**
- 无证据的意见（"代码很乱"）
- 无解决方案的抱怨（"认证很糟"）
- 未来功能的想法（那是产品规划的事）
- 普通的 TODO（那些在代码注释中）
- 运行良好的架构决策
- 小代码风格问题

**填充此模板时：**
- **始终包含文件路径**——没有位置的关注点是不可执行的。使用反引号：`src/file.ts`
- 用测量值具体说明（"500ms p95" 而非"慢"）
- 包含 bug 的复现步骤
- 建议修复方法，而不仅是问题
- 聚焦于可执行的事项
- 按风险/影响排列优先级
- 问题解决后更新
- 发现新问题时添加

**语气指南：**
- 专业化，不情绪化（"N+1 查询模式" 而非"糟糕的查询"）
- 面向解决方案（"修复：添加索引" 而非"需要修复"）
- 以风险为导向（"可能暴露用户数据" 而非"安全性很糟"）
- 事实性（"3.5s 加载时间" 而非"真的很慢"）

**在以下场景中对阶段规划有用：**
- 决定下一步做什么
- 估计变更的风险
- 理解哪里需要小心
- 优先排序改进
- 引导新的 Claude 上下文
- 规划 重构 工作

**此文件如何填充：**
Explore agent 在代码库映射期间检测到这些问题。欢迎人工添加人工发现的问题。这是动态文档，不是抱怨清单。
</guidelines>
