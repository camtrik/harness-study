# 里程碑条目模板

完成里程碑时，将此条目添加到 `.planning/MILESTONES.md`：

```markdown
## v[X.Y] [名称]（发布于：YYYY-MM-DD）

**交付：** [一句话描述发布了什么]

**已完成阶段：** [X-Y]（总共 [Z] 个计划）

**主要成就：**
- [重大成就 1]
- [重大成就 2]
- [重大成就 3]
- [重大成就 4]

**统计：**
- [X] 个文件创建/修改
- [Y] 行代码（主要语言）
- [Z] 个阶段，[N] 个计划，[M] 个任务
- [D] 天从开始到发布（或里程碑到里程碑）

**Git 范围：** `feat(XX-XX)` → `feat(YY-YY)`

**下一步：** [简要描述下一个里程碑目标，或"项目已完成"]

---
```

<structure>
如果 MILESTONES.md 不存在，使用以下标题创建：

```markdown
# 项目里程碑：[项目名称]

[条目按时间倒序排列——最新的排最前]
```
</structure>

<guidelines>
**何时创建里程碑：**
- 初始 v1.0 MVP 已发布
- 大版本发布（v2.0、v3.0）
- 重大功能里程碑（v1.1、v1.2）
- 归档规划之前（捕获已发布的内容）

**不要为以下情况创建里程碑：**
- 单个阶段完成（正常的工作流）
- 正在进行中的工作（等到发布后再说）
- 不构成一次发布的小 bug 修复

**要包含的统计：**
- 统计修改的文件数：`git diff --stat feat(XX-XX)..feat(YY-YY) | tail -1`
- 统计代码行数：`find . -name "*.swift" -o -name "*.ts" | xargs wc -l`（或相关扩展名）
- 来自 ROADMAP 的阶段/计划/任务计数
- 从第一个阶段的 commit 到最后一个阶段的 commit 的时间线

**Git 范围格式：**
- 里程碑的第一个 commit → 里程碑的最后一个 commit
- 示例：`feat(01-01)` → `feat(04-01)` 对应阶段 1-4
</guidelines>

<example>
```markdown
# 项目里程碑：WeatherBar

## v1.1 安全与完善（发布于：2025-12-10）

**交付：** 安全加固，集成 Keychain 和全面的错误处理

**已完成阶段：** 5-6（总共 3 个计划）

**主要成就：**
- 将 API 密钥存储从明文迁移到 macOS Keychain
- 实现了网络故障的全面错误处理
- 添加了 Sentry 崩溃报告集成
- 修复了自动刷新定时器中的内存泄漏

**统计：**
- 23 个文件修改
- 新增 650 行 Swift
- 2 个阶段，3 个计划，12 个任务
- 从 v1.0 到 v1.1 共 8 天

**Git 范围：** `feat(05-01)` → `feat(06-02)`

**下一步：** v2.0 SwiftUI 重新设计，支持小组件

---

## v1.0 MVP（发布于：2025-11-25）

**交付：** 菜单栏天气应用，显示当前天气和 3 天预报

**已完成阶段：** 1-4（总共 7 个计划）

**主要成就：**
- 带弹出界面（AppKit）的菜单栏应用
- OpenWeather API 集成，支持自动刷新
- 带天气条件图标的当前天气显示
- 带高低温的 3 天预报列表
- 代码签名并公证以供分发

**统计：**
- 47 个文件创建
- 2,450 行 Swift
- 4 个阶段，7 个计划，28 个任务
- 从开始到发布共 12 天

**Git 范围：** `feat(01-01)` → `feat(04-01)`

**下一步：** v1.1 安全审计和加固
```
</example>
