# Planner 来源审计与权限限制

`agents/gsd-planner.md` 的参考——多来源覆盖审计和 planner 权限约束的扩展规则。

## 多来源覆盖审计格式

在最终确定计划之前，生成覆盖所有四种产物类型的**来源审计**：

```
来源     | ID      | 功能/需求                    | 计划    | 状态        | 备注
--------- | ------- | ---------------------------- | ----- | --------- | ------
GOAL      | —       | {来自 ROADMAP.md 的阶段目标}   | 01-03 | 已覆盖      |
REQ       | REQ-14  | OAuth 登录（Google + GH）    | 02    | 已覆盖      |
REQ       | REQ-22  | 邮件验证流程                  | 03    | 已覆盖      |
RESEARCH  | —       | 认证路由上的速率限制          | 01    | 已覆盖      |
RESEARCH  | —       | 刷新 Token 轮换              | NONE  | ⚠ 缺失    | 无计划覆盖此
CONTEXT   | D-01    | JWT 使用 jose 库             | 02    | 已覆盖      |
CONTEXT   | D-04    | 15 分钟访问 / 7 天刷新       | 02    | 已覆盖      |
```

### 四种来源类型

1. **GOAL**——ROADMAP.md 中此阶段的 `goal:` 字段。主要的成功条件。
2. **REQ**——`phase_req_ids` 中的每个 REQ-ID。交叉引用 REQUIREMENTS.md 获取描述。
3. **RESEARCH**——RESEARCH.md 中确定的技术方法、发现的约束和功能。排除研究员明确标记为"超出范围"或"未来工作"的项目。
4. **CONTEXT**——CONTEXT.md `<decisions>` 节中的每个 D-XX 决策。

### 什么不是差距

不要将以下标记为 MISSING：
- CONTEXT.md `## Deferred Ideas` 中的项目——开发者选择延迟这些
- 通过 `phase_req_ids` 分配给不同阶段的项目——未分配给此阶段
- RESEARCH.md 中研究员明确标记为"超出范围"或"未来工作"的项目

### 处理 MISSING 项

如果任何行为 `⚠ MISSING`，不要静默完成计划集。返回给编排器：

```
## ⚠ 来源审计：发现未计划项

以下来自来源产物的项目没有对应计划：

1. **{来源}：{项目描述}**（来自 {产物文件}，"{节}"节）
   - {为什么这被认定为必需}

   选项：
   A) 添加一个计划覆盖此项目
   B) 拆分阶段：移到子阶段
   C) 显式延迟：添加到 backlog 并获得开发者确认

   → 等待开发者决策后再最终确定计划集。
```

如果所有行都显示 COVERED → 正常返回 `## PLANNING COMPLETE`。

## 权限限制——约束示例

Planner 拆分或标记功能的唯一合法理由是**约束**，而非对难度的判断：

**有效（约束）：**
- ✓ "此任务涉及 9 个文件且将消耗约 45% 的上下文——拆分为两个任务"
- ✓ "任何来源产物中均未定义 API key 或端点——需要开发者输入"
- ✓ "此功能依赖于在阶段 03 中构建的认证系统，该阶段尚未完成"

**无效（难度判断）：**
- ✗ "这很复杂且难以正确实现"
- ✗ "与外部服务集成可能花费很长时间"
- ✗ "这是一个有挑战性的功能，可能更适合留给未来的阶段"

如果一个功能没有三个合法约束中的任何一个（上下文成本、缺失信息、依赖冲突），它就应该被规划。就这样。
