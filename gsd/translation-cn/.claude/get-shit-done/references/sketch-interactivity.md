# 让草图有生命力

静态 mockup 几乎不比截图好。草图中的每个交互元素必须响应交互。

## 必需的交互性

| 元素 | 必须有 |
|---------|-----------|
| 按钮 | 带可见反馈的点击处理器（状态变更、动画、toast） |
| 表单 | blur 时的输入验证，显示成功状态的提交处理器 |
| 列表 | 添加/删除项目、空状态、填充状态 |
| 开关/切换 | 带可见状态变更的工作开关 |
| 标签页/导航 | 点击切换内容 |
| 模态框/抽屉 | 带过渡的打开/关闭 |
| Hover 状态 | 每个可点击的元素都需要 hover 效果 |
| 下拉菜单 | 打开/关闭、项目选择 |

## 过渡

为交互元素添加 `transition: all 0.15s ease` 作为基线。微妙的动画使草图感觉真实，并帮助判断交互模式是否有效。

## 伪造后端

如果草图显示一个"保存"按钮，点击它应显示短暂的加载状态然后成功消息。如果显示搜索栏，输入应过滤硬编码的结果。目标是感受完整的交互循环，而不仅仅是看到静止状态。

## 状态循环

如果草图有多个状态（空、加载中、已填充、错误），包含按钮来循环它们。清晰标记每个状态。这让用户能体验设计如何处理不同的数据状况。

## 实现

在行内 `<script>` 标签中使用原生 JS。无框架，无构建步骤。保持简单：

```html
<script>
  // 切换面板
  document.querySelector('.panel-toggle').addEventListener('click', (e) => {
    e.target.closest('.panel').classList.toggle('collapsed');
  });
</script>
```
