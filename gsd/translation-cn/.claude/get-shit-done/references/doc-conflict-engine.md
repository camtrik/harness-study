# 文档冲突引擎

工作流将外部内容引入 `.planning/` 时的共享冲突检测合约（例如 `/gsd-import`、`/gsd-ingest-docs`）。定义报告格式、严重性语义和安全门行为。填充每个严重性桶的具体检查是工作流特定的，由调用方工作流定义。

---

## 严重性语义

- **[BLOCKER]**（阻塞）——不安全，不能继续。工作流必须退出，不写入任何目标文件。用于锁定决策的矛盾、缺失前置条件、不可能的目标。
- **[WARNING]**（警告）——模糊或部分重叠。工作流必须显示警告并获得用户的明确批准才能写入。绝不自动批准。
- **[INFO]**（信息）——仅供参考。无门控；不需要用户提示。包含在报告中以提高透明度。

---

## 报告格式

纯文本，不使用 markdown 表格（无 `|---|`）。报告原样呈现给用户。

```
## 冲突检测报告

### 阻塞（{N}）

[BLOCKER] {简短标题}
  发现：{来源内容所述}
  期望：{现有项目上下文所需}
  → {解决的具体操作}

### 警告（{N}）

[WARNING] {简短标题}
  发现：{检测到的问题}
  影响：{可能出现的问题}
  → {建议的操作}

### 信息（{N}）

[INFO] {简短标题}
  备注：{相关信息}
```

每个条目需要 `发现：` 加上 `期望：`/`影响：`/`备注：` 三者之一，加上（对于 BLOCKER/WARNING）一个 `→` 修复行。

---

## 安全门

**如果有任何 [BLOCKER] 存在：**

显示：
```
GSD > 已阻塞：在 {操作} 继续之前必须解决 {N} 个阻塞项。
```

退出，不写入任何目标文件。无论 WARNING/INFO 计数如何，门卫必须保持。

**如果只有 WARNING 和/或 INFO（无阻塞）：**

呈现完整报告，然后通过 `references/gate-prompts.md` 中的 `approve-revise-abort` 或 `yes-no` 模式提示审批。遵守文本模式（参见工作流自身的文本模式处理）。如果用户中止，则干净退出并显示取消消息。

**如果报告为空（所有桶中都没有条目）：**

静默继续或显示 `GSD > 未检测到冲突。` 两者皆可；工作流根据详细程度上下文选择。

---

## 工作流职责

每个使用此合约的工作流必须定义：

1. **每个桶自身的检查列表**——哪些条件属于 BLOCKER/WARNING/INFO。这些是领域特定的（计划导入检查不同于文档导入检查）。
2. **加载的上下文**——在运行检查之前读取什么（ROADMAP.md、PROJECT.md、REQUIREMENTS.md、CONTEXT.md、intel 文件）。
3. **操作名词**——替换到 BLOCKED 横幅中的词（`import`、`ingest` 等）。

工作流不得：

- 引入 BLOCKER/WARNING/INFO 之外的新严重性级别
- 将报告渲染为 markdown 表格
- 在存在 BLOCKER 时写入任何目标文件
- 在无用户输入的情况下自动批准 WARNING

---

## 反模式

不要：

- 在冲突报告中使用 markdown 表格（`|---|`）——使用上面展示的纯文本标签
- 在存在 BLOCKER 时绕过安全门——"轻微"阻塞也不例外
- 将 WARNING 降级为 INFO 以跳过审批提示——如果需要用户输入，它就该是 WARNING
- 每个工作流重新发明严重性标签——三级分类是固定的
