# 默认模式 — 交互式讨论阶段

> **延迟加载。** 当没有模式标志存在时（基线交互式流程），从 `workflows/discuss-phase.md` 读取此文件。当 `--text`、`--batch` 或 `--analyze` 也存在时，将相应的叠加文件叠加在下面的规则之上。

此文档定义了默认流程的 `discuss_areas`。之前的共享步骤（`initialize`、`check_blocking_antipatterns`、`check_spec`、`check_existing`、`load_prior_context`、`cross_reference_todos`、`scout_codebase`、`analyze_phase`、`present_gray_areas`）位于父文件中，并为每种模式运行。

## discuss_areas（默认，交互式）

对于每个选定的区域，进行聚焦的讨论循环。

**提问前研究模式：** 检查配置中是否启用了 `workflow.research_before_questions`。当启用时，在呈现每个区域的问题之前：
1. 对与该区域主题相关的最佳实践进行简要网络搜索
2. 以 2-3 个要点总结主要发现
3. 将研究与问题一起呈现，以便用户做出更明智的决策

**理念：** 保持适应性。默认流程是 4 个单问题回合，然后检查是否继续。每个答案应揭示下一个问题。

**对于每个区域：**
1. 宣布区域
2. 使用 AskUserQuestion 询问 4 个问题（附具体选项和代码上下文注释）
3. 检查是否继续更多问题还是移至下一区域
4. 处理"Other"（自由文本）响应
5. 所有初始选定区域完成后，提供探索更多灰色区域或准备上下文的选项

**讨论期间的规范引用累积：** 当用户在任何回答中引用文档、规范或 ADR 时，立即读取引用的文档并添加到规范引用累积器中。

**思维伙伴（条件性）：** 如果启用了 `features.thinking_partner`，提供权衡分析。

**范围蔓延处理：** 捕获阶段领域之外的想法到推迟的想法，重定向回当前讨论。

**增量检查点 — 每个区域完成后保存。** 检查点文件防止进度丢失。会话恢复在父文件的 `check_existing` 步骤中处理。

**内部追踪讨论日志数据：** 对于每个问题，累积区域名称、呈现的选项、用户选择以及任何澄清或后续笔记。
