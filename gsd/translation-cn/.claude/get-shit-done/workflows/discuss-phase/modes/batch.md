# --batch 模式 — 分组问题批次

> **延迟加载叠加。** 当 `$ARGUMENTS` 中存在 `--batch` 时，从 `workflows/discuss-phase.md` 读取此文件。可与 default、`--all`、`--chain`、`--text`、`--analyze` 组合。

## 参数解析

从 `$ARGUMENTS` 解析可选的 `--batch`：
- 接受 `--batch`、`--batch=N` 或 `--batch N`
- 未提供数字时默认**每个批次 4 个问题**
- 将显式大小限制在 **2–5** 之间，使批次保持可回答
- 如果没有 `--batch`，保持现有的一次一个问题流程（默认模式）。

## 对 discuss_areas 的影响

`--batch` 模式：每个区域在**一个纯文本回合中**询问 **2–5 个编号问题**，而不是默认的 4 个单问题 AskUserQuestion 回合。

- 将当前区域的密切相关问题分组为单条消息
- 保持每个问题具体且可在一个回复中回答
- 当选项有帮助时，每个问题包含简短的内联选项
- 用户回复后，反映捕获的决策，记录任何未回答项，并仅询问最少量的后续内容
- 在批次之间保持适应性

## 理念

保持适应性，但让用户选择节奏。
- 默认模式：4 个单问题回合，然后检查是否继续
- `--batch` 模式：1 个分组回合包含 2–5 个编号问题，然后检查是否继续

每组答案应揭示下一个问题或下一个批次。
