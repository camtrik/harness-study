# 计划文档审查者 prompt 模板

在 dispatch 计划文档审查者 subagent 时使用此模板。

**用途：** 验证计划是否完整、是否与 spec 匹配，以及是否有适当的任务分解。

**Dispatch 时机：** 完整计划编写完成之后。

```
Task tool (general-purpose):
  description: "Review plan document"
  prompt: |
    你是一个计划文档审查者。验证此计划是否完整且可以实施。

    **待审查的计划：** [PLAN_FILE_PATH]
    **参考 spec：** [SPEC_FILE_PATH]

    ## 检查内容

    | 类别 | 检查要点 |
    |----------|------------------|
    | 完整性 | TODO、占位符、未完成的任务、缺失的步骤 |
    | Spec 对齐 | 计划覆盖了 spec 需求，没有重大范围蔓延 |
    | 任务分解 | 任务边界清晰，步骤可执行 |
    | 可构建性 | 工程师能否在不卡住的情况下按照此计划实施？ |

    ## 校准

    **仅标记会在实施过程中造成实际问题的 issues。**
    实施者构建了错误的东西或卡住才是一个问题。
    措辞、风格偏好和"最好有"的建议不是问题。

    除非存在严重漏洞——缺失 spec 中的需求、矛盾的步骤、占位符内容，或任务过于模糊而无法执行，否则应批准。

    ## 输出格式

    ## 计划审查

    **状态：** 已批准 | 发现问题

    **问题（如有）：**
    - [任务 X，步骤 Y]：[具体问题] - [为什么这对实施重要]

    **建议（咨询性，不阻止批准）：**
    - [改进建议]
```

**审查者返回：** 状态、问题（如有）、建议
