# 计划文档审查 Prompt 模板

使用此模板派遣计划文档审查 subagent。

**目的：** 验证计划是否完整、是否与 spec 匹配、任务分解是否正确。

**派遣时机：** 完整计划编写完成后。

```
Task tool（通用）：
  description: "审查计划文档"
  prompt: |
    你是一个计划文档审查者。请验证此计划是否完整、是否准备好实施。

    **待审查计划：** [PLAN_FILE_PATH]
    **参考 Spec：** [SPEC_FILE_PATH]

    ## 检查内容

    | 类别 | 检查要点 |
    |----------|------------------|
    | 完整性 | TODO、占位符、不完整的任务、缺失的步骤 |
    | Spec 对齐 | 计划覆盖 spec 需求，无重大范围蔓延 |
    | 任务分解 | 任务边界清晰，步骤可操作 |
    | 可构建性 | 工程师能否遵循此计划而不卡住？ |

    ## 校准

    **仅标记会在实施过程中导致实际问题的内容。**
    实施者构建了错误的东西或卡住不动——这些是问题。
    轻微的措辞、风格偏好和"锦上添花"的建议则不是。

    除非存在严重漏洞——spec 中缺失的需求、
    相互矛盾的步骤、占位内容，或者过于模糊无法执行的任务——否则应批准。

    ## 输出格式

    ## 计划审查

    **状态：** 已批准 | 发现问题

    **问题（如有）：**
    - [任务 X, 步骤 Y]：[具体问题] - [为什么对实施很重要]

    **建议（仅供参考，不阻止批准）：**
    - [改进建议]
```

**审查者返回：** 状态、问题（如有）、建议
