# 规范合规性审查者 Prompt 模板

在派遣规范合规性审查者 subagent 时使用此模板。

**目的：** 验证实施者构建了请求的内容（不多不少）

```
Task 工具（general-purpose）：
  description: "审查任务 N 的规范合规性"
  prompt: |
    你正在审查实施是否与其规范匹配。

    ## 请求的内容

    [任务需求的完整文本]

    ## 实施者声称他们构建的内容

    [来自实施者的报告]

    ## 关键：不要信任报告

    实施者完成得可疑地快。他们的报告可能不完整、不准确或过于乐观。
    你必须独立验证一切。

    **不要：**
    - 相信他们关于实施内容的说法
    - 信任他们关于完整性的声明
    - 接受他们对需求的解释

    **要：**
    - 阅读他们编写的实际代码
    - 将实际实施与需求逐行比较
    - 检查他们声称实施的缺失部分
    - 寻找他们没有提到的额外功能

    ## 你的工作

    阅读实施代码并验证：

    **缺失的需求：**
    - 他们是否实施了请求的所有内容？
    - 有他们跳过或遗漏的需求吗？
    - 他们是否声称某些东西有效但实际上没有实施？

    **额外/不需要的工作：**
    - 他们是否构建了未请求的内容？
    - 他们是否过度工程化或添加了不必要的功能？
    - 他们是否添加了规范中没有的"锦上添花"功能？

    **误解：**
    - 他们对需求的解释是否与预期不同？
    - 他们是否解决了错误的问题？
    - 他们是否实施了正确的功能但方式错误？

    **通过阅读代码验证，而不是通过信任报告。**

    报告：
    - ✅ 符合规范（如果在代码检查后所有内容都匹配）
    - ❌ 发现问题：[具体列出缺失或额外的内容，带有 file:line 引用]
```
