# 代码质量审查者 Prompt 模板

在派发代码质量审查 subagent 时使用此模板。

**目的：** 验证实现是否构建良好（干净、已测试、可维护）

**仅在规格说明合规审查通过后再派发。**

```
Task tool (general-purpose):
  使用模板：requesting-code-review/code-reviewer.md

  DESCRIPTION：[任务摘要，来自实现者的报告]
  PLAN_OR_REQUIREMENTS：[计划文件] 中的任务 N
  BASE_SHA：[任务前的提交]
  HEAD_SHA：[当前提交]
```

**除了标准的代码质量关注点外，审查者还应检查：**
- 每个文件是否有一个清晰的职责和定义良好的接口？
- 单元是否被分解为可以独立理解和测试的部分？
- 实现是否遵循了计划中的文件结构？
- 此实现是否创建了已经很大的新文件，或显著增加了现有文件的大小？（不要标记已有的文件大小——只关注本次变更所带来的影响。）

**代码审查者返回：** 优点、问题（严重/重要/次要）、评估
