# 规范文档审查者提示模板

在派发规范文档审查者 subagent 时使用此模板。

**目的：** 验证规范是完整的、一致的，并准备好进行实施规划。

**派发时机：** 规范文档已写入 docs/superpowers/specs/

```
Task tool (general-purpose):
  description: "审查规范文档"
  prompt: |
    你是一个规范文档审查者。验证此规范是完整的并准备好进行规划。

    **要审查的规范：** [SPEC_FILE_PATH]

    ## 检查内容

    | 类别 | 寻找什么 |
    |----------|------------------|
    | 完整性 | TODO、占位符、"TBD"、不完整的部分 |
    | 一致性 | 内部矛盾、冲突的要求 |
    | 清晰性 | 要求足够模糊，可能导致某人构建错误的东西 |
    | 范围 | 足够专注于单个计划——不涵盖多个独立的子系统 |
    | YAGNI | 未请求的功能、过度工程 |

    ## 校准

    **仅标记会在实施规划期间导致真正问题的 issues。**
    缺失的部分、矛盾，或模糊到可以有两种解释的要求——这些都是 issues。轻微的措辞改进、风格偏好和"比其他部分不太详细的部分"不是。

    除非有导致有缺陷计划的严重差距，否则批准。

    ## 输出格式

    ## 规范审查

    **状态：** 已批准 | 发现问题

    **问题（如果有）：**
    - [第 X 部分]：[具体问题] - [为什么对规划很重要]

    **建议（咨询性，不阻止批准）：**
    - [改进建议]
```

**审查者返回：** 状态、问题（如果有）、建议
