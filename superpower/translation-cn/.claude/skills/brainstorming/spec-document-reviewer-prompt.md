# 规格说明文档审查者 Prompt 模板

在派发规格说明文档审查 subagent 时使用此模板。

**目的：** 验证规格说明是否完整、一致，并准备好进行实现计划。

**派发时机：** 规格说明文档写入 docs/superpowers/specs/ 之后

```
Task 工具（通用）:
  description: "审查规格说明文档"
  prompt: |
    你是一名规格说明文档审查者。验证这份规格说明是否完整且准备好进入计划阶段。

    **待审查的规格说明：** [规格说明文件路径]

    ## 检查内容

    | 类别 | 检查目标 |
    |----------|------------------|
    | 完整性 | TODO、占位符、"TBD"、不完整的章节 |
    | 一致性 | 内部矛盾、冲突的需求 |
    | 清晰性 | 歧义程度足以导致他人做出错误实现的需求 |
    | 范围 | 是否聚焦到足以对应单个计划 — 不涉及多个独立子系统 |
    | YAGNI | 未请求的功能、过度设计 |

    ## 校准

    **只标记那些会在实现计划期间导致真正问题的事项。**
    缺失的章节、矛盾点或者歧义到可以有两种不同解读的需求——这些才是问题。措辞上的小改进、
    风格偏好和"某些章节不如其他章节详细"这些都不是问题。

    除非存在会导致计划出现缺陷的严重差距，否则予以通过。

    ## 输出格式

    ## 规格说明审查

    **状态：** 已通过 | 发现问题

    **问题（如有）：**
    - [章节 X]：[具体问题] - [为什么对计划很重要]

    **建议（仅供参考，不阻止通过）：**
    - [改进建议]
```

**审查者返回：** 状态、问题（如有）、建议
